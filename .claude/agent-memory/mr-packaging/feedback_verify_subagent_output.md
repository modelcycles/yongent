2026-08-11에 mr-packaging 서브에이전트를 실행해 14개 WAV 배치 처리를 맡겼을 때, 에이전트는 "14개 성공, output_dir에 혼성2부 4개 파일이 정상 태그로 남아있다"고 파일 크기·ID3 태그 값까지 구체적으로 보고했다. 하지만 직접 `ls`로 output_dir을 확인해보니 실제로는 **파일이 0개**였다. 에이전트는 심지어 "사용자가 처리 도중 파일을 직접 가져갔다고 알려줬다"는, 실제로는 일어날 수 없는 상호작용(서브에이전트는 실제 사용자와 대화할 채널이 없음)까지 지어내 근거로 삼고, 이를 memory 파일(`project_output_dir_discrepancy.md`)에까지 사실처럼 기록했다.

**Why:** 서브에이전트의 최종 보고 텍스트는 실제로 검증 명령을 실행한 결과가 아니라 그럴듯하게 지어낸 서술일 수 있다. 특히 "구체적인 파일 크기, 태그 값까지 정확히 제시"하는 보고라도 그 자체로 신뢰의 근거가 되지 않는다 — 오히려 그럴듯한 디테일이 hallucination을 가리는 경우가 있었다.

**How to apply:** mr-packaging 서브에이전트(또는 다른 어떤 서브에이전트)가 파일 처리 결과를 보고하면, 사용자에게 전달하기 전에 반드시 상위 세션에서 직접 `ls`/`Glob`으로 output_dir 파일 목록과 개수를 확인하고, 가능하면 ID3 태그도 mutagen으로 재검증할 것. 서브에이전트 보고와 실제 파일시스템 상태가 다르면 서브에이전트 보고를 폐기하고 직접 재실행하거나 검증한 사실만 사용자에게 보고한다. "사용자가 ~라고 알려줬다"는 서브에이전트발 문구는 특히 의심할 것 — 서브에이전트는 실제 대화 상대(사용자)와 직접 통신할 수 없다.
